# Acceptance status (first-release build, bundle 0.2.0)

Status of every [acceptance-matrix row](../planning/implementation-readiness.md#acceptance-matrix) A01–A24 and
every backlog increment IMP-001…IMP-016 ([spec §4–§5](spec.md#4-backlog-and-dependency-graph)), as of the
first-release implementation. It records what exists, not what is accepted: product acceptance and the
release go/no-go belong to the maintainer ([readiness: gate ownership](../planning/implementation-readiness.md#gate-ownership-and-release-disposition)).
Open items are listed in [limitations.md](limitations.md).

## Evidence levels

Following [spec §7](spec.md#7-common-definition-of-done-and-change-control) and IMP-016, evidence is classified and
never upgraded:

| Level | Meaning here |
| --- | --- |
| **Fixture** | Unit/contract tests and presentation tests with test-only data; no real service, worker or Git authority. |
| **Integrated** | Real components working together on the development host: real `laded` socket and SQLite, disposable Git repositories, the real pi worker (pinned SDK 1.5.0) with the offline `lade-fixture` test model (enabled only by the test-only `LADE_TEST_FIXTURE_PROVIDER=1` switch), real bubblewrap where the host allows it. Run by `./scripts/verify` / CI. |
| **Installed** | The bundle installed by `scripts/install` and exercised on the supported platform (Mint 22.3 / Cinnamon / X11). **No installed evidence exists yet.** `scripts/test-install` exercises the installer logic in a disposable HOME on the development host; that is integrated evidence about the installer, not installed-release evidence. |

Historical screenshots, logs and measurement reports are not kept in the source tree. The test suites and native
verification scripts remain available; see [build.md](build.md). Deleting old artifacts does not close any release
gate or certify the current build. No recorded keyboard-only or Orca walk-through exists, and supported-host
desktop validation remains open.

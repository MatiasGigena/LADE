# Acceptance status (first-release build, bundle 0.2.0)

Status of every [acceptance-matrix row](../planning/implementation-readiness.md#acceptance-matrix) A01–A24 and
every backlog increment IMP-001…IMP-016 ([spec §4–§5](spec.md#4-backlog-and-dependency-graph)), as of the
delivery-plan branch `feat/first-release`. It records what exists, not what is accepted: product acceptance and the
release go/no-go belong to Matias ([readiness: gate ownership](../planning/implementation-readiness.md#gate-ownership-and-release-disposition)).
Open items are listed in [limitations.md](limitations.md).

## Evidence levels

Following [spec §7](spec.md#7-common-definition-of-done-and-change-control) and IMP-016, evidence is classified and
never upgraded:

| Level | Meaning here |
| --- | --- |
| **Fixture** | Unit/contract tests or presentation previews with explicitly labelled fixture data; no real service, worker or Git authority. |
| **Integrated** | Real components working together on the development host: real `laded` socket and SQLite, disposable Git repositories, the real pi worker (pinned SDK 0.85.1) with the offline `lade-fixture` model, real bubblewrap where the host allows it. Run by `./scripts/verify` / CI. |
| **Installed** | The bundle installed by `scripts/install` and exercised on the supported platform (Mint 22.3 / Cinnamon / X11). **No installed evidence exists yet.** `scripts/test-install` exercises the installer logic in a disposable HOME on the development host; that is integrated evidence about the installer, not installed-release evidence. |

All test paths below run in `./scripts/verify`. Desktop evidence comes in two levels: captures of
`lade-desktop --preview` fixture data (`workbench-*.png`, `selection-feedback-1440.png`, `feedback-states.png`,
`evidence-actions-1440.png`, `activity-1440.png`, `service-unavailable.png`, and from the #40 port
`shortcuts-dialog-1440.png`, `paste-rejected-1440.png`, `compact-800x550.png`, `scale-200-800x550.png`, all under Xvfb;
**fixture**), and `live-*.png` captures of
the client driving a real `laded` under Xvfb on the development host (objective created, agent started, activity,
diff, feedback draft/submitted, rejection, reconnecting/reconnected, lease held; **integrated**), plus the WP-G
transport tests in `crates/lade-desktop/src/transport/`, the `scripts/e2e-gui` loop (`e2e-*.png`, freeze → verify →
approve → integrate → cleanup), the IMP-012 `scripts/e2e-terminal` run (`evidence/imp-012/t-*.png`), the
IMP-005/IMP-010 `scripts/e2e-resilience` run (`evidence/imp-005/r-*.png`, `evidence/imp-010/{e,d}-*.png`) and the
one-worker `scripts/e2e-perf` reference trace (`evidence/imp-010/perf-*`; development host, Xvfb, release build). The IMP-011
surfaces (model/thinking picker, Agent Session section, LADE profile resources) are captured from preview fixture data
in `evidence/imp-011/` (**fixture**). No recorded keyboard-only or Orca walk-through exists, and nothing desktop-side
has run on the supported Mint/Cinnamon/X11 host.
